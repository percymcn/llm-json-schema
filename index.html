        OpenAI · strict
        
Invalid schema for response_format: 'additionalProperties' is required to be supplied and to be false.

        
Every object needs additionalProperties: false

        
In strict mode OpenAI requires additionalProperties: false on every object in the schema — including nested ones. Missing it on any level fails the whole request.

        
Fix → Convert to OpenAI adds it everywhere.

        OpenAI · strict
        
Invalid schema: required is required to be supplied and to be an array including every key in properties.

        
All fields must be in required

        
Strict mode has no concept of optional fields — every property must appear in required. To keep a field effectively optional, make it nullable with "type": ["string", "null"].

        
Fix → Convert forces required and nullables the ones you left out.

        Full fix + examples →
        openai structured outputs docs ↗
      


      

        OpenAI · strict
        
Invalid schema: 'anyOf' is not permitted at the root level.

        
Root can't be anyOf (or a non-object)

        
The root of a strict schema must be an object and must not use anyOf. Move the union down into a property. allOf, not, and if/then/else aren't supported at all.

        
Fix → Convert flags a root anyOf and strips unsupported composition keywords.

        openai structured outputs docs ↗
      


      

        Gemini · responseSchema
        
Fields returned in an unpredictable order / wrong order in structured output.

        
Gemini needs propertyOrdering

        
Gemini decides field order from propertyOrdering, an array of property names. Without it, output order is unstable and can hurt quality. It's part of Gemini's schema subset, not standard JSON Schema.

        
Fix → Convert to Gemini adds propertyOrdering to every object.

        gemini structured output docs ↗
      


      

        Gemini · responseSchema
        
400 INVALID_ARGUMENT: Unknown name "$ref" / "pattern" in responseSchema.

        
Gemini supports only a schema subset

        
No $ref/$defs, no pattern, no minLength/maxLength. String format is limited to date-time, date, and time. Anything else must be removed or inlined.

        
Fix → Convert to Gemini drops unsupported keywords and flags $ref.

        Anthropic · input_schema
        
tools.0.input_schema: Input should be a valid dictionary / not an object schema.

        
input_schema is standard JSON Schema

        
Anthropic tool input_schema is ordinary JSON Schema with an object root — no forced-required, no additionalProperties rule. For guaranteed conformance, add strict: true to the tool definition, not the schema.

        
Fix → Convert to Anthropic keeps your schema and notes the strict option.
